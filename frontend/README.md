# CardioTwin Frontend

React 19 + Vite + TypeScript + Tailwind. One screen: the dashboard. The project
overview is in the [root README](../README.md).

## Run

```bash
npm ci
npm run dev        # http://localhost:5173, for development
npm run build
npm run preview    # http://localhost:4173, for presenting
```

The backend must be running. Requests to `/api` and `/ws` are proxied to
`http://localhost:8000`, or to `CARDIOTWIN_API` when it is set.

## Layout

| Path | What it holds |
|------|---------------|
| `src/App.tsx` | The dashboard and its URL state (`#dashboard/<lamina>/<animation\|graph\|table>`). |
| `src/components/dashboard/` | The four zones, the outcome tiles, the trend grid, the table and the Inspect drawer. |
| `src/components/twin/` | Panels the dashboard and Inspect are built from: inputs, stage, map, functions, segments, loop, composites. |
| `src/hooks/` | `useCardioStream` (the live socket) and `useLaminaTwin` (structure and values kept on the same lamina). |
| `src/twin/` | The schema index, the view registry, outcome helpers, and the stage template the heart artwork is bound through. |
| `public/heart/` | The heart artwork and its `template.json`, generated by `tools/heart/cut_heart_layers.py`. |

The rule the screen is built on: structure comes from the lamina schema, values
come from the live tick, and nothing comes from a constant typed into a
component. `src/twin/stageRegistry.tsx` is the one exception, because artwork
cannot be derived from a schema.
